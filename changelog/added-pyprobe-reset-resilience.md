pyprobe-rs sessions now survive unexpected target resets and power cycles. RTT streaming keeps running across a firmware re-initialization (the server re-attaches the control block per poll) while the background poller makes the quiet window visible and warns when a subscribed channel vanishes from a rebuilt control block. If the target loses power or the probe is replugged mid-session, the next operation rebuilds the transport, re-attaches, restores DWARF debug info and tracked hardware breakpoints, and retries — once per session, with later failures surfaced unchanged. Server-side failures are now classified into script-branchable `.kind` values (`Probe`, `Rtt`, `Core`, `Memory`, `Timeout`) from the probe-rs error text.
